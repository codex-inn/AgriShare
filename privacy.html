AgriShare privacy notice

Prototype notice · last updated 13 October 2026. This notice describes the intended use of data in this student prototype. It is not a substitute for an institution-approved privacy policy or legal review.

Information the app may process

  • Username and authentication identifiers needed to sign in.
  • Equipment listing details that an owner chooses to publish, such as equipment name, category, rate, village/service area and optional photo URL.
  • Optional machine-specification photos or PDFs uploaded to private storage for manual review. They are restricted to the equipment owner and project maintainers.
  • Booking details supplied by a farmer, including preferred date, acreage, field location, notes and phone number where the booking form requests it.
  • Group booking and membership details needed to coordinate shared work.
  • Messages exchanged by the farmer and equipment owner for an active booking.
  • A village or town entered for weather or map lookup. The weather/map lookup sends that search text to the relevant public provider; the app does not need precise device location for this feature.
  • A crop image only after the user checks a separate consent box for that scan; it is sent to the HTTPS CropSight endpoint the user enters, whose operator sets its own retention practices.
  • A support, listing-safety, account-access or account-deletion request submitted by a signed-in user.
  • A rating and optional comment after a booking is marked completed; these reviews are visible only to the two booking participants.

How data is used

Account data supports sign-in. Public equipment listings and open group summaries support discovery. Booking details and private messages support coordination between the involved farmer and equipment owner. Bundle requests create a separate request for each selected equipment owner; the phone number is shared with each owner only after consent. Optional specification evidence is private to the equipment owner and project maintainers. Weather lookup uses Open-Meteo; map tiles use OpenStreetMap. Crop images are sent only after per-scan consent to the HTTPS endpoint configured by the user. AgriShare does not verify arbitrary endpoints; the endpoint operator may process or retain the image under its own terms. Signed-in support requests enter a restricted Supabase queue for project administrators to review. Reviews are shared only with the other participant in the completed booking. Review each provider's own privacy terms before submitting information.

Visibility and safety

Support queue submissions are not publicly readable through the app. Project administrators can access records in the connected Supabase project. Do not publish passwords, identity documents or sensitive personal information. Do not upload personal records as equipment-specification evidence. A phone number supplied for a booking should be shared only for the stated coordination purpose and with the user's consent. Public listing visibility depends on the live database policies; do not assume all fields are private without verifying the deployed schema and policies. No payment processing is provided by this prototype.

Retention and account requests

Data may remain in the connected Supabase project until removed by an authorized project administrator. Private specification evidence is removed when its equipment listing is deleted. Signed-in users can submit an account-deletion request through Help & support; it is a manual request and does not immediately delete the account or data. Support requests are stored in a restricted table and may be read by project administrators. Do not use the public issue tracker for account or personal data. Username accounts currently have no self-service password-reset flow.

Security and limitations

The project uses Supabase authentication and row-level security, but the full deployed system still requires review and testing. Do not rely on this prototype for sensitive or urgent transactions. Before public launch, the project team must identify a responsible privacy contact, define retention periods, validate all table policies, and obtain institutional/legal review.
